# 视觉卡库 · 抽取提示词（v3）

> 交给 Codex（browser use）执行。目标是做一个类似 `~/ArxivDaily` 的仓库：README 就是 reel，打开就能看到大量高质量参考图。每张卡是一种**视觉语言**，配一组震撼的参考截图，并把风格和核心手法写清楚，方便直接迁移到 Crepuscular Citadel 博客的 3D 场景和 UI。
> 旧版 257 张机制卡保留，作为工程备注，不进入新库。

---

## 0. 一句话任务

用浏览器逐个打开 3D 参考作品，像美术指导一样找出最好看的那些画面，高质量截图。按「视觉语言」把截图归成卡：每张卡讲清一种可迁移的风格做法（光影、构图、材质、排版……），配 3–8 张来自不同作品的参考图，并写明在我们博客的什么地方怎么用。

## 1. 什么是一张卡

卡的单位是**一种视觉语言**，不是一个仓库，也不是一段代码。

- 好的卡名：「逆光剪影巨构」「黑镜水面倒影」「霓虹湿地反射」「高度雾分层纵深」「冷暖分离主光」「HUD 细线叠层」「巨字压画面排版」「特写起步拉远镜头」
- 坏的卡名：「Singularity 项目」「把句前停顿与下载延迟合并计时」「使用 EffectComposer」

一张卡 = 一个视觉判断 + 一组证明这个判断的参考图 + 迁移到我们博客的做法。参考图最好来自 2 个以上不同作品，说明这是一种普遍成立的语言，而不是某个作品的偶然。

## 2. 抽取流程（browser use）

### 2.1 看
1. 按 `~/Blog/PORTS.md` 起本地 demo（端口从 3001 起，一律 `--strictPort`），或打开在线 demo / 作者主页 / 作品视频页。
2. 先当观众看完整体验：首屏、滚动、交互、镜头运动、转场、昼夜/状态变化。
3. 每个作品记 3–10 个「最好看的一刻」，用观众语言写一句为什么好看。

### 2.2 截
- 视口 1920×1080（必要时 2560×1440，deviceScaleFactor 2），等资源和后期完全加载后再截，不截加载中、报错、半透明遮罩、调试面板。
- 交互/动画作品：找到最好的那一帧再截（暂停、拖到时间点、固定 seed）；必要时连截 3–5 帧做连续序列，或录 3–6 秒短片转 webp/mp4。
- 每张图记录：来源作品、URL/端口与路由、机位或交互步骤、时间点、截图日期。写进 `SOURCE.md`，保证别人能复现同一画面。
- 允许裁切出局部细节图（材质、水面、光晕边缘），但必须同时保留一张全画面图。
- headless 走 SwiftShader 时画质可能下降；画面明显劣化就改用有 GPU 的有头浏览器截。

### 2.3 拆
对每张入选图，按第 4 节的维度逐项拆解：这张图好看，**具体是哪几个维度在起作用**。只写看得见的东西。

### 2.4 归卡
把拆解结果相同的图归到同一张卡。一张图可以出现在多张卡里，但每张卡里都要写清它在这张卡里证明的是什么。

### 2.5 查源码（只为迁移）
只在需要写「怎么做」时才去读源码，找出产生效果的关键几行，给出永久链接和关键参数。源码是配方，不是卡本身。

## 3. 收录门槛

1. **甩图测试**：把卡里的参考图发给建模/美术同学，说「做成这种感觉」，对方能看懂要什么。
2. **震撼测试**：缩到 400px 宽，仍然好看、仍然有一眼的冲击力。平庸的图宁可不收。
3. **方向一致**：符合博客基调（巨构、史诗、赛博朋克、可带修仙古风）。禁区：紫色渐变、玻璃拟态、Inter 字体、「Scroll ↓」（见 `CrepuscularIRIS.github.io/docs/design/DESIGN.md`）。
4. **不收**：作者宣传海报、README logo、编辑器界面、设置面板、纯代码截图、加载/报错画面。
5. **不收非视觉**：TTS 时序、组件注册、数据加载这类机制一律不进新库。

## 4. 视觉维度表（拆解与归卡都用这张表）

每张卡在「拆解」一节里，挑出起作用的维度逐条写，至少 4 个维度。每条都要落到图上的具体位置，并尽量给数值（hex、比例、角度、亮度百分比）。

### A. 光影
| 维度 | 要回答的问题 |
|---|---|
| 主光方向 | 顺光 / 侧光 / 逆光 / 顶光 / 底光？主光在画面哪里？ |
| 光源类型 | 太阳、天光、发光体（霓虹、屏幕、吸积盘）、点光、体积光？ |
| 光比与明暗结构 | 暗部占画面多少？最亮点在哪？是低调（大面积暗）还是高调？ |
| 轮廓光 / 边缘光 | 主体边缘有没有一圈光把它从背景里分出来？颜色？ |
| 阴影 | 硬阴影还是软阴影？接触阴影/AO 是否让物体落地？ |
| 发光与光晕 | bloom 的阈值和扩散范围？光晕是否吃掉结构？ |
| 光的叙事 | 光把视线引到哪？光是否在讲时间（黄昏、深夜、事件发生）？ |
| 反射与高光 | 高光形状、反射里能看到什么？ |

### B. 色彩
| 维度 | 要回答的问题 |
|---|---|
| 主色与辅色 | 画面由哪 1–2 个色相主导？给出 hex |
| 冷暖关系 | 冷暖如何分区（暖光冷影 / 冷环境暖焦点）？ |
| 饱和度分布 | 高饱和只出现在哪里？大面积是否降饱和？ |
| 明度阶梯 | 黑、暗灰、中灰、亮、高光各占多少？ |
| 调色风格 | tone mapping 曲线、色偏、胶片颗粒、色差？ |
| 点缀色 | 有没有一个小面积强对比色做视觉锚点？ |

| 画框与比例 | 横幅宽银幕 / 竖幅 / 画中画？裁切是否果断？ |

## 6.1 实现索引（2026-10-28 起，卡的第二层）

卡的主体仍是一种视觉语言（第 6 节模板不变）。在此之上，每张卡再带一层**实现索引**，让打磨方案只引用卡 id（`card:<id>`）就能找到「去哪拿、怎么接进 citadel」，不必再从头翻仓库。

写在两处：`card.json` 的 `impl` 数组（机器可读，director/judge 检索用），以及 README「做法」节末尾的「实现索引」表（人读）。

```json
"impl": [
  {
    "work": "Clearwater",
    "source": "Repos/clearwater/src/caustics.frag:12-48",
    "technique": "一句话：它是怎么做出这个效果的",
    "params": [{"name": "causticScale", "value": "0.35", "kind": "源码"}],
    "license": "MIT",
    "reuse": "integrate | borrow | reference",
    "citadel": "src/world/worlds/cardfx/caustics-on-receivers.js | 已落地 <场景>:<文件> | none"
  }
]
```

规则：

1. `source` 必须是 `~/Blog/Repos/` 下已 clone 仓的**文件与行**，打开读过才能写；作品网址不算实现。作品无源码时写 `"source": "none"`，并在 `technique` 里给最近的邻接技术源路径。
2. `params[].kind` 只能是 `实测`（从画面量）、`源码`（源码里的值）、`建议迁移值`（为 citadel 估的起点），不得混写。
3. `reuse`：`integrate`（MIT 等许可允许，可直接集成/移植代码）· `borrow`（只借手法，Prosperity / 无 LICENSE 必须是这一档）· `reference`（只参考构图与画面）。
4. `citadel`：citadel 里已有的可复用实现路径；预制效果模块统一放 `citadel/src/world/worlds/cardfx/<card-id>.js`（首次在场景落地时由执行者沉淀）；尚未集成写 `none`。代码只放 citadel，atlas 只放链接。
5. 一张卡可以有多条 `impl`（不同作品、不同实现路线）。实现索引不改变收卡标准：视觉弱的作品即使有好源码也不收。

## 7. 配方（`recipes/<id>.md`）

配方用来验证卡能不能组装成一个完整场景，比如：

- **事件视界下的黑水港**：黑洞透镜背景 + 吸积盘逆光 + 黑镜水面倒影 + 低高度雾 + 剪影巨构 + 特写起步拉远
- **雨夜霓虹街口**：霓虹主光 + 湿地反射 + 雨丝与雾 + 冷暖分离
- **云海上的古风阶梯城**：黄昏天空 + 云海体积 + 风化石材 + 灯笼点光 + 仰视尺度

配方表写清每个维度由哪张卡负责、在这个组合里怎么调参。另外逐条检查：

1. 光源逻辑：每一处亮光都能指认来源吗？
2. 色彩逻辑：主色、辅色、点缀色是否各只有一个？
3. 明暗结构：暗部、中间调、高光各由谁负责，有没有抢？
4. 尺度：前中后景各有尺度参照吗？
5. 冲突：所选卡的「冲突」字段之间有没有撞上？

配方附一组参考图拼板（来自各卡），作为场景的情绪板。

## 8. README（reel）要求

学 `~/ArxivDaily/README.md` 的 Featured Reel，但要以图为主：

- 顶部：一句话说明这个库是什么，加 3–6 张最震撼的图组成首屏横幅。
- 按分组分节（光影 / 色彩 / 构图重心 / 造型尺度 / 材质 / 水与大气 / 镜头运动 / 排版 UI / 配方）。

做法：
1. 先跑一个脚本，从上述数据文件把条目导出成 `screening/<collection>.csv`，列：`id, 标题, 链接/本地路径, 类型(3D/2D/UI/视频/非视觉), 结论(收/不收/打不开), 一句理由, 截图文件`。
2. 先按标题和描述粗筛掉明显非视觉的条目（文本工具、代码助手、数据处理），在 CSV 里标「非视觉」，不必打开。
3. 其余每一条都用浏览器打开看（视频就看片并在最好的时间点截帧），填结论和一句理由。打不开、链接失效、需要登录的标「打不开」并写原因。
4. 收下的条目按第 2 节截图、按第 4 节拆解、归到卡里。
5. 每个合集筛完，在 `sources.md` 写一段汇总：看了多少、收了多少、收下的进了哪些卡。
6. 可以分批、多 agent 并行，每个 agent 只写自己负责的 CSV 段，不改别人的文件。

条目数量大，**不要求每条都进卡**，要求每条都有结论。宁可 663 条里只收 20 条好的。

可以补外部来源：作品在线站点、Awwwards / Codrops / Shadertoy 上公开的高质量 3D 网页，必须在 `SOURCE.md` 写清 URL 和许可。

不做：`miniflux`、`readability`、`excalidraw`、`newsnow`、`letta*`、`mem0`、`SillyTavern`、`TrendRadar`、`json-render` 等非 3D 视觉来源。

许可：`lygia`、`gsap-threejs-codrops`、`opus55-live-demos` 只借思路，不贴代码。图片保留原作者权利，`SOURCE.md` 注明出处。
