# web-ocean
新增WebGPU纯shader海洋案例。实际查看front/side/high三张历史静帧：海面近中远有层次，正对太阳有纵向金色反光，侧视保留深青水体，高机位可见泡沫碎片。源码是6级FFT、LEAN坡度统计、世界坐标泡沫历史及两层平面云；不是动态/性能验收。README作者自述Claude Code Opus5.5，模型归因未独立证实。

## 领域分析

海面的可信度来自尺度分工与统一光照；先稳定高光，再增加浪花。

### 画面与证据

已实际查看docs/front.jpg、side.jpg、high.jpg历史静图：正视图的暖太阳反射与青绿海面相对，侧视图没有同样的强反射带，俯视图可读泡沫。由此推论其构图价值是视角相关的反射与波面层次；三张图不能证明波动连续性、泡沫平流或当前HEAD性能。

### 因果链

- 源码事实：六级256网格，尺度1103、211.3、39.7、7.43、1.393、.2617；互补频带把大起伏与小波面分开（js/main.js:20–39、427–438，common:1–8）。
- 源码事实：波面斜率矩与mip统计参与粗糙度，未解析微波转成反射宽度（ocean:125–193；sim:255–275）。因果推论：远景应减少针点闪烁，但必须用运动验证。
- 源码事实：泡沫按Jacobian注入、平流、指数衰减；有限太阳盘7点可见度影响水面高光；cloud footprint与Karis首级降采样分别约束边缘与孤立亮点（OCN-003至006）。

### 审美决策

- 大浪承担轮廓，中浪承担节奏，小浪承担反射，不让所有频带都争夺注意。
- 泡沫应说明浪曾经在哪里，反射应说明太阳当前在哪里。
- 云与水共享光照原因；后期只整理动态范围。

### 相邻方案

电影可先锁一条中近景轨道验证分层；前端可从现有水材质增加斜率方差或共享太阳遮挡。若只需静态远海，烘焙环境与低频波面比迁整套WebGPU模拟更合适。

### 迁移顺序

- 在已有海面固定相机、曝光、太阳和总波能量，分别关掉各频带，明确每层职责。
- 先迁一个增量：远景粗糙度补偿；再用缓慢推远检验高光是否稳定。
- 再加世界坐标泡沫记忆，录制浪峰消失后的残留；最后比较有/无太阳遮挡耦合。

### 局限

MIT代码不等于已验证实时预算；未运行。本仓平面云近似不能写成完整体积云。Citadel已有多尺度水与部分共享天空/云影，应按OCN卡的查重结果选增量。

- 完整FFT/WebGPU迁移不等于当前场景打磨

泡沫不是每帧阈值白斑；它记录浪峰经过的痕迹。高机位静图只显示白沫存在，不证明这些历史状态运行正确。

**Movie：prototype** · 波浪近景可明确看到残留差异

- 无岸线模型却拿它当海岸冲浪
