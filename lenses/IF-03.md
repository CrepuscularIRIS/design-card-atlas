# IF-03 · 信息与操作的空间映射
用户看见的对象、点击区域、键盘焦点以及结果面板是否指向同一个东西？

前端空间不只是布局美感，它是操作坐标的约定。DOM与GPU双层、窗口堆叠、移动端重排都可能破坏这份约定。实验台的输入—对象—结果顺序与阅读页的标题—正文顺序是不同的空间组织。

## 诊断问题

- 标出每个可见对象的DOM入口、命中区域、可访问名称与焦点归属，避免Canvas上一个对象、HTML里另一个入口。
- 检查字体/图片晚到、浏览器缩放、resize之后，视觉矩形与操作矩形是否一起更新。
- 响应式重排优先保持因果邻接：调节参数时看得到对象及至少一个结果，而非机械按桌面栏序堆叠。
- 悬浮工具与内容分层，但真正的输入焦点必须跟随视觉前后顺序；关闭工具应回到合理位置。

## 失败信号

- 视觉卡片移动了，点击仍落在旧位置。
- 看起来最前面的窗口不能输入，隐藏窗口却接收键盘。
- 手机sticky视图占满可用高度，控件滚不到或焦点被遮挡。

## 最小对照

在慢字体加载、200%缩放、窄屏和弹窗打开四态，用鼠标和键盘操作同一对象；视觉、命中、焦点对象必须一致。对DOM/GPU叠层以2px作为候选项目内误差门槛，不能当通用标准。

## 归纳边界

图像对齐不能代替键盘与读屏测试；本维度只讨论信息与操作几何，不承担3D镜头构图评价。
